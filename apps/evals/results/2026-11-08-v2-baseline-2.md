# Zoom baseline of the fixed `v2`: ten models, 20 programs, 2026-11-08

Raw results: [`2026-11-08-v2-baseline-2.json`](2026-11-08-v2-baseline-2.json) (200 runs, the raw text of every attempt included). Run with `pnpm baseline:run` from `apps/evals`, on commit `1ee2ea1` with a clean tree (the file records it). View it with `pnpm report results/2026-11-08-v2-baseline-2.json`. This is the second full run of `v2`: the first, [`2026-11-07-v2-baseline.json`](2026-11-07-v2-baseline.json) (write-up: [`2026-11-07-v2-baseline.md`](2026-11-07-v2-baseline.md)), led to three fixes (commit `6bd6645`), and this run repeats it on the fixed `v2` so that every cell has the same prompt. It is compared with `v0` and `v1` from [`2026-11-07-baseline.json`](2026-11-07-baseline.json) and with the first run. **Every number below is computed from the stored text with the validators of `1ee2ea1`, the code this run was made on, for all of them,** so the first run's numbers here differ from its own write-up (172 valid, not 169: the fixes are in the validators now). The criteria are the ones fixed before the first run in section 6 of `planning_documents/prompt_evaluation_and_improvements_v3.md`; none was changed for this run.

## What was run

The 20 programs of the corpus with `v2` on the same ten models, one sample each, under the baseline's parameters (`temperature` 0.2 where the model takes one, `maxTokens` 32768, each model's default reasoning, each model pinned to one provider through LiteLLM): 200 runs, 54 minutes (10:58 to 11:52 UTC on 2026-11-08), recorded cost $1.35. `v2` here differs from the first run's `v2` in one prompt line (a built-in block that changes shape with its state needs the `extraState` the Detail JSON gives it, as `controls_if` with an else does) and in two proxy changes that apply when output is scored: an empty list in an input means nothing runs inside it, and a block definition with references that no block uses is dropped with a repair note.

By the decision rule of plan v3, C1 to C3 are met, so **`v2` qualifies as a candidate default**, to be decided after a human has looked at its output. C4 and C5 each fail in part. The rule says a single failed criterion among C4 to C8 is a finding to read; it does not say what to do with two, so that is a decision, not a verdict (see "Outcome").

## Reading the two that failed

- **C4 is mostly a count of labels, as in the first run.** A valid zoom has 9.4 block definitions against `v1`'s 7.25, and 7.6 Semantic blocks against 5.4. Leaks per definition are 0.78 against 0.73, and on the six models that were reliable under both prompts (`claude-haiku-5.5`, `gemini-3.5-flash-lite`, `glm-5.3-flash`, `minimax-m3`, `deepseek-v4.1-flash-1017`, `qwen3.8-27b`) 0.79 against 0.77. The references did not lower the rate of values in labels, and the metric is noisy: D17 flags a label that contains any Detail string field of three or more characters, so a program's name ("FizzBuzz") or an enum value (`WHILE`, `ADD`) counts.
- **C5's one failing part is confined to the three weaker models.** The plan misses 6 stacks in 182 valid zooms, all in `gpt-5.4-nano`, `qwen3-coder-next` and `gemma-4-26b-a4b-it` (plan coverage 40 of 46 for those three; 120 of 120 for the six reliable models, whose concept count is also in range in 120 of 120). A valid zoom is not a good one, and the models that `v2` recovers write poorer plans. The plan is internal, so a retry on a plan that misses a stack is the lever (plan v3, section 7, step 5).

## Other findings

- **Stacks stay together:** 0 of 182 valid zooms are split, and 0 of the six reliable models' 120.
- **Valid but does not load: 6 of 182 (3.3%),** against 8 of 169 in the first run (7 of 172 re-scored) and 1 of 155 for `v1`. Five are `qwen3-coder-next`: four zoom statement blocks that cannot connect to their parent and one `variables_get` missing its previous connection. One is `gpt-oss-20b`, a `controls_if` with an `ELSE` and no `extraState`. The `controls_if` failures fell from four to one after the prompt line, which is consistent with it working but is one sample. The six reliable models have none.
- **The 18 failures:** 13 validation (a reference to a variable, `{bN.VAR}`, 4 times; a reference to a field the block does not have, such as `TEXT` or `NUM` on `variables_get`, `ADD0` on `lists_create_with`, `PLAYER` on `logic_boolean`, 8 times; a block that cannot follow another, once); 2 invalid JSON (`gpt-oss-20b`); 1 schema (`qwen3-coder-next`: a block type without the `zoom_` prefix); 2 truncated (`gpt-oss-20b`, whose last attempt hit the output cap: 48,074 output tokens over three attempts on `fizzbuzz` and 60,271 on `quiz`).
- **The proxy repaired a missing `%N` in a block's message 52 times** in 200 runs (a model declared an arg and left its `%N` out of the message), and added a missing `input_statement` arg 5 times. That is invisible to the user and costs no retry, but it says how often models leave these out.
- **The Semantic level is still bigger than `v1`'s:** 7.6 blocks per valid zoom against 5.4 (+41%). The pictures of `v2` are drawn separately.
- **Cost and time:** $1.35 against $1.33 for `v1`, a mean of 93 seconds per run against 142, 1.41 attempts per run against 1.59.

## Limits

- One sample per cell and small L and XL cells (4 and 1 programs). C1 to C3 are judged on totals and whole models; the run-to-run variation above says a weak model's count moves by about three runs.
- A valid zoom is not a good one. No judge or person has rated `v2`; this write-up does not cover its pictures, which are drawn and written up separately (plan v3, section 7, step 2).
- The criteria and their thresholds were set before the first run and were not changed, but the first run led to the fixes, so this run is a second look at the same criteria, not an independent test.
- The validators are those of `1ee2ea1`.

## Outcome

Nothing is adopted by this write-up. `v2` is not frozen and is not the default. What the data supports: it passes C1 to C3, so it is a candidate; it passes C6 to C8 and part of C5; it fails C4 and the plan-coverage part of C5, both by the measures fixed beforehand. What decides adopting it is a human look at its pictures, whether the plan-coverage and concept-count checks should become blocking, and whether the +41% Semantic size is acceptable.
