# Zoom baseline of `v2`: ten models, 20 programs, 2026-11-07

Raw results: [`2026-11-07-v2-baseline.json`](2026-11-07-v2-baseline.json) (200 runs, the raw text of every attempt included). Run with `pnpm baseline:run` from `apps/evals`, on commit `f6cd31d` with a clean tree (the file records it). View it with `pnpm report results/2026-11-07-v2-baseline.json`. The comparison is with `v0` and `v1` from [`2026-11-07-baseline.json`](2026-11-07-baseline.json), the earlier baseline. **Every number below is computed from the stored text with the validators of `f6cd31d`, the code the run was made on, for all three prompts,** so they can be reproduced by checking that commit out. Later commits change what a re-score gives (see "Outcome"). The criteria are the ones fixed before the run in section 6 of `planning_documents/prompt_evaluation_and_improvements_v3.md`.

## What was run

The 20 programs of the corpus with the `v2` prompt on the same ten models, one sample each, under the baseline's parameters (`temperature` 0.2 where the model takes one, `maxTokens` 32768, each model's default reasoning, each model pinned to one provider through LiteLLM): 200 runs. The run took 47 minutes (23:30 UTC on 2026-11-07 to 00:17 UTC on 2026-11-08). Recorded cost $1.43, against $1.33 for the 200 `v1` runs.

`v2` differs from `v1` in how the model writes what users edit and where the blocks go (plan v3, sections 4 and 5): a value is written as a reference in the label (`{b12.NUM}`) and the proxy makes the field and the binding; a level's blocks are written as `stacks`, flat lists, and the proxy builds the nested `next` chains; and the prompt has rules on connecting the blocks of a stack, on a statement input for a "do" block, on where a zoom block may sit in a built-in block, and no bound dropdowns. The plan, the outline and the level rules are `v1`'s. Two smoke runs on `countdown` and `dice-game` came before it and changed the format once (nested `next` to stack lists) and fixed one repair.

By the decision rule of plan v3, C1 to C3 must be met for `v2` to be a candidate default, and C2 is not, so **it is not yet one.** C4 and C5 are findings to read, below.

## Reading the three that failed

- **C2 is two runs of `gemini-3.5-flash-lite`,** and both were the proxy being stricter than it needed to be: a loop input written as an empty list (`DO: []`), which means nothing runs inside it, and a block definition with a reference that no block uses. Neither says anything about the model.
- **C4 is mostly a count of labels, not more leaking per label.** A valid `v2` zoom has 9.9 block definitions against `v1`'s 7.25, and 7.6 Semantic blocks against 5.4. Leaks per definition are 0.81 against 0.73. On the six models that were reliable under both prompts (`claude-haiku-5.5`, `gemini-3.5-flash-lite`, `glm-5.3-flash`, `minimax-m3`, `deepseek-v4.1-flash-1017`, `qwen3.8-27b`) they are 0.75 against 0.77, with 10.2 definitions per zoom against 7.35. So the references did not lower the rate of values in labels (H17 is not supported), and the metric is also noisy: D17 flags a label that contains any Detail string field of three or more characters, so program names such as "FizzBuzz" and enum values such as `WHILE` or `ADD` count. The three models `v2` newly makes valid are worse: `gpt-5.4-nano`, `qwen3-coder-next` and `gemma-4-26b-a4b-it` leak 1.01 per definition against 0.62 for `v1`.
- **C5 misses come from the same newly valid models.** On the six reliable models the concept count is in range in 116 of 117 valid zooms (`v1`: 112 of 113) and the plan covers every stack once in 117 of 117 (`v1`: 113 of 113). On the three weaker models it is 39 of 47 and 40 of 47. All 7 plans that miss a stack are `gpt-5.4-nano` (5) and `qwen3-coder-next` (2): five list the one Detail stack under more than one concept and two list it under none. A valid zoom is not a good one, and the models that `v2` recovers write poorer plans.

## Other findings

- **Stacks stay together.** Split Semantic stacks fell from 22.6% to 0.6% of valid zooms; on programs with one Detail stack, from 19 of 53 to 1 of 62. On the six reliable models: 0 of 117, against 14 of 113.
- **More zooms are valid but do not load: 8 of 169 (4.7%)** against 1 of 155 for `v1`. Four are `controls_if` blocks with an `ELSE` or `IF1` input and no `extraState` (the mutation Blockly needs for it): `minimax-m3` three times, `qwen3-coder-next` once. Four are zoom statement blocks that cannot connect to their parent, all `qwen3-coder-next`. The proxy cannot check a built-in block's shape without Blockly.
- **The 13 validation failures** were: a reference to a variable (`{bN.VAR}`, a variable field holds an object, not a value) 4 times; a reference to a field the block does not have (`TEXT` on `variables_get`, `ADD0` on `lists_create_with`, `SPEED` on `robot_drive`) 7 times; a definition used by two blocks once; a definition no block uses once. The 2 schema failures: an empty `DO` list (`gemini-3.5-flash-lite`) and a label with a `%N` and no arg (`qwen3-coder-next`).
- **The Semantic level is bigger:** 7.6 blocks per valid zoom against 5.4 (+41%), and 8.1 against 5.5 on the six reliable models. Whether it is less abstract or just more complete is not measured here; it needs the pictures.
- **Faster and cheaper to repeat:** mean 84 seconds per run against 142, and 1.41 attempts per run against 1.59. Recorded cost per run is a little higher ($1.43 against $1.33 in total).

## Limits

- One sample per cell and small L and XL cells (4 and 1 programs), so a difference of one or two runs is not a finding. C1 to C3 are judged on totals and whole models; C2's failure is two runs.
- `gpt-oss-20b` is mostly missing, as above, and C1 passes with or without it.
- A valid zoom is not a good one. Nothing here measures whether a label is true, whether a behaviour was left out, or whether the Semantic level is the right size; no judge or person has rated `v2`, and its pictures were not drawn.
- The validators are those of `f6cd31d`. Two later changes alter what stored text re-scores to: a repair that no longer repeats a `%N`, and the leniency for an empty input list and an unused definition. They are in the next section.

## Outcome

Nothing is decided by this write-up beyond the rule's reading above. After the run, commit `6bd6645` made the proxy accept an empty input list and drop an unused definition, and added a line to the `v2` prompt telling the model to give a built-in block its `extraState`. Re-scoring this run's stored text with the two code changes gives 172 of 200 valid (both `gemini-3.5-flash-lite` failures and one `qwen3-coder-next` run now pass, so C2 would pass) and leaves `v0` at 168 and `v1` at 155; the prompt line cannot be replayed. A full rerun of the fixed `v2` under a new run id is planned, so that every cell has the same prompt.
